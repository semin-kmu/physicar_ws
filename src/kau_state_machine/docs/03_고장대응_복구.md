# 03. 고장 대응 / 복구

`02` 가 검출한 이상에 **어떻게 대응하고 어떻게 되돌리는가**.
검출 규칙은 `02`, System 상태 전이 정의는 `04`.

<br>

## 1. 범위

| 포함 | 미포함 |
| --- | --- |
| MRM (정지 등급과 수단) | 이상 검출 규칙 → `02` |
| Soft Reset / Hard Restart | System 상태 전이 정의 → `04` |
| 복구 중 연쇄 오탐 억제 | 프로파일별 경로 생성 → 각 파트 |
| 정보 주입, 복구 검증 | |
| 재engage 판정, 한도 초과 처리 | |
| 보존/동결 대상 | |

<br>

---

## 2. 원칙

| 원칙 | 내용 |
| --- | --- |
| **정지가 먼저** | 복구 이전에 정지. 움직이며 재시작하지 않는다. 예외는 section 8 에서만 |
| **약한 수단부터** | Lifecycle → 프로세스. 프로세스 재시작은 상태를 전부 잃는다 |
| **복구 단위는 노드** | 패키지 전체를 재시작하지 않는다. `localization` 을 살리려다 `ekf` 를 죽이면 `map→odom` 복구 전략이 무너짐 |
| **Mission 은 동결, 리셋 아님** | 랩 진행도·이벤트 이력은 복구를 통과해 살아남아야 한다 (section 12) |
| **오탐이 재시작보다 위험** | 정상 노드를 재시작하는 것이 실주행 최대 실패 모드. 복구 진입 조건은 `02` 의 확정 절차를 반드시 통과 |
| **복구가 새 고장을 만들지 않게** | 복구 중 의존 노드가 연쇄로 이상 판정되는 것을 막아야 한다 (section 7) |

## 3. 대응 결정

```
02 등급 확정
   ↓
fallback 성립 여부 판정 (02 section 7-4 의 프로파일별 필수 입력 집합)
   ↓
┌─ 성립  → 프로파일 전환 + 속도 하향 → 주행 계속 → 배후에서 복구 (section 8)
└─ 불성립 → MRM 정지 (section 4) → 복구 (section 5·section 6) → 검증 (section 9) → 재engage (section 10)
```

| 등급 | fallback | 대응 |
| --- | --- | --- |
| `DEGRADED` | 성립 | **정지하지 않음.** 프로파일 전환 + 속도 하향, 주행 중 복구(section 8) |
| `DEGRADED` | 불성립 | `speed_limit = 0` → 정차 → 복구 |
| `FAULT` | - | **`enable` 차단 정지** → 복구 |

<br>

### 3-1. 노드별 대응 · 확정

**이 표가 1차 구현 범위. 여기에 없는 대응은 만들지 않음.**

| 노드 | 이상 확정 시 | 복구 | **복구 불가 판정 시** |
| --- | --- | --- | --- |
| `localization` | **`enable` 차단 정지** | Hard Restart + `initial_pose` 주입 (section 6-4) | **`lane_only` 로 지속 주행: 도착 판정 없음** |
| `lane_detection` | **정지 없음** | 주행 중 복구 (section 8) | **`global_only` 로 주행 계속** |
| `object_detection` | **`enable` 차단 정지** | Soft → Hard | **포기 → `TERMINATED`** (회피 불가) |
| `local_path_planner` | **`enable` 차단 정지** | Soft → Hard | **포기 → `TERMINATED`** (회피 경로 생성 불가) |
| `steer_controller` | **`enable` 차단 정지** | Soft → Hard | **포기 → `TERMINATED`** |
| `speed_controller` | **`enable` 차단 정지** | Soft → Hard | **`state_machine` 이 상수 속도 대행** (section 4-4) |
| `global_path_planner` | **정지 없음** | 복구 시도 | 주행 계속: **별도 대응 없음** |
| `map_server` | 정지 없음 | 복구 시도 | 주행 계속 |
| `ekf` / laser odometry | **`enable` 차단 정지** | Hard Restart | **포기 → `TERMINATED`** |
| `state_machine` | (자동 정지, section 4-3) | Soft → Hard | **포기 → `TERMINATED`** |

**정지 없이 계속 가는 노드는 3개뿐**. `lane_detection`, `global_path_planner`, `map_server`

| 판단 | 근거 |
| --- | --- |
| `global_path_planner` 예외처리 없음 | 기동 시 1회 생성 후 idle → **고장 가능성이 실질적으로 없음**. 경로는 이미 전달됨 |
| `object_detection` 포기 | 라바콘 회피가 불가능해지므로 주행을 계속할 근거가 없음 |
| `local_path_planner` 포기 | 경로 생성 주체 자체. 대체 수단 없음 |
| `speed_controller` 만 대행 가능 | 상수 속도로도 완주는 가능. 조향은 대행 불가 |

- `localization` 은 **먼저 정지·복구를 시도**하고 실패한 뒤에 `lane_only` 로 간다 (section 8-2)
- `FAULT` 는 정의상 "남는 입력이 없음"(`02` section 7-4) → fallback 판정 불필요

## 4. MRM

### 4-1. 정지 수단 2가지 · 등급 구분 없음

**모든 정지는 즉시 정지.** 감속 프로파일을 두지 않음.

| 수단 | 발동 | 동작 | 주체 | 지연 |
| --- | --- | --- | --- | --- |
| **`/state_machine/speed_limit = 0`** | `DEGRADED` + fallback 불성립, `STOP_AND_WAIT`, `FINISHED` | 컨트롤러가 `/speed = 0` **즉시** 출력 | `state_machine` | 1 tick (50 ms) |
| **`/state_machine/enable` 발행 중단** | `grade == FAULT` | Deadman 만료 → 컨트롤러가 스스로 안전값 | `system_supervisor` | 250 ms |

**감속 프로파일을 없앤 이유**

| 항목 | 판단 |
| --- | --- |
| 쓰이던 곳 3군데 | `DEGRADED` 복구 전 정지 / `STOP_AND_WAIT` / `FINISHED`: **셋 다 부드럽게 설 이유가 없다** |
| `STOP_AND_WAIT` | **오히려 반대**: 전방이 막혔는데 천천히 서는 것이 위험 |
| `FINISHED` | 도착선 통과 후이므로 기록에 영향 없음. 급정지 손해도 없음 |
| 감속률 파라미터 | **미실측**(`a` 가정값)에 의존: 튜닝 안 된 프로파일은 거동이 예측 불가 |
| 분기 제거 | "언제 부드럽게, 언제 급하게"를 판단하는 로직이 사라짐 |

- 정지 경로가 하나이므로 로그에서 **"왜 이렇게 섰는가"를 물을 필요가 없음**
- `Pull Over` 없음. 순회 트랙에 갓길이 없음

**두 수단을 합치지 않는 이유**. 커버하는 고장이 다름

| | `enable` 차단 | `speed_limit = 0` |
| --- | --- | --- |
| 커버 | Supervisor tick 정지·사망, `FAULT` | `state_machine` tick 정지·사망, 미션 판단 |
| 상대가 죽어도 | `speed_limit` 은 정상 발행될 수 있음 | `enable` 은 정상 발행될 수 있음 |

### 4-2. 조향은 즉시 0 금지

**구동만 즉시 끊고 조향은 수렴.**

| 처리 | 결과 |
| --- | --- |
| `/speed = 0` **즉시** | 구동 차단 |
| `/steer` = **직전 값 유지 후 0 으로 수렴** | 자세 유지하며 정지 |
| `/steer` 를 즉시 `0` | **곡선 구간에서 차선 이탈**: 금지 |

- 수렴 시간 `steer_zero_tau` 는 정지 소요 시간과 같은 크기. 값은 section 15
- 속도와 조향의 처리가 다른 이유: 구동 차단은 **즉시 안전**이지만 조향 차단은 **즉시 위험**

### 4-3. `state_machine` 이 죽은 경우

- `speed_limit = 0` 은 `state_machine` 이 발행하므로 **그 노드가 죽으면 불가능**
- 이때는 `/state_machine/speed_limit` 이 stale → 컨트롤러가 자동으로 `0` (`01` 계약 17) → **결과적으로 정지**. 별도 대비 불필요

### 4-4. `speed_controller` 대행 · 복구 불가 시

**`speed_controller` 복구를 포기하면 `state_machine` 이 `/speed` 를 직접 발행.**

| 항목 | 규정 |
| --- | --- |
| 발행값 | **상수 = 구간 상한의 25 %**. 곡률 기반 산출 없음 |
| 발행 주기 | `state_machine` tick 과 동일 (**20 Hz**). ⚠ 평시 `/speed` 주기가 미정이므로 **차량 인터페이스가 20 Hz 를 수용하는지 확인 필요** (section 15) |
| 진입 조건 | `speed_controller` 프로세스가 **완전히 종료**되었음을 확인한 뒤 |
| 해제 | `speed_controller` 가 다시 살아나는 경로는 없음 (복구 포기 상태) |
| Deadman | **`state_machine` 도 enable Deadman 을 구현**: 미수신 시 `0`. 공용 구현 사용 (`01` 계약 12) |

**동시 발행 절대 금지**

- `/speed` 에 발행자가 둘이면 **두 값이 번갈아 나가 차량이 진동**함
- Supervisor 가 프로세스 종료(`poll()` 반환)를 확인한 **뒤에** 대행 시작을 지시
- 대행 중에는 `speed_controller` 를 **재spawn 하지 않음** (복구 포기 상태이므로 자동으로 성립)

**대행의 한계. 인지하고 쓸 것**

| 잃는 것 | 결과 |
| --- | --- |
| 곡률 기반 감속 | 급커브에서도 상수 속도 → **상수값을 최소 곡률 반경 기준으로 정해야 함** |
| EMA 평활 | 계단 변화: 상수이므로 무관 |
| 속도 상한 반영 | `state_machine` 이 발행자이므로 자기 상한을 그대로 적용 |

- 비율값은 **완주 가능한 최저 속도**로 잡음. 기록보다 완주가 우선
- 속도는 전 문서에서 **구간 상한 대비 비율로만** 규정 (`02` section 7-4)
- 조향은 대행할 수 없음. `steer_controller` 가 죽으면 포기 (section 3-1)

## 5. 복구 수단 2계층

| 계층 | 수단 | 커버 고장 | 소요 | 상태 |
| --- | --- | --- | --- | --- |
| **Soft Reset** | Lifecycle `deactivate → cleanup → configure → activate` | 내부 상태 오염, 초기화 실패 | 수백 ms | 프로세스 유지 |
| **Hard Restart** | `killpg` → 재spawn → configure → activate | 크래시, hang, OOM | 수 s | 전부 소실 |

**분류별 가용 수단** (`01` section 2-1)

| 분류 | 노드 | Soft Reset | 비고 |
| --- | --- | --- | --- |
| A 자체 Lifecycle | `object_detection` `lane_detection` `global_path_planner` `local_path_planner` `state_machine` `speed_controller` `steer_controller` | **가능** | - |
| B 외부 Lifecycle | `map_server`, `amcl`(채택 시) | **가능** | - |
| C 외부 non-Lifecycle | `ekf`, `cartographer`(채택 시) | **불가** | **바로 Hard Restart** |

- 분류 C 가 존재한다는 것은 **복구 비용이 노드마다 다르다**는 뜻 → `localization` 알고리즘 선정 시 이 차이를 성능과 함께 볼 것 (`02` section 12)
- Soft Reset 이 의미를 가지려면 `on_cleanup` 이 상태를 **실제로 씻어내야** 한다 (`01` 계약 11)

## 6. 복구 절차

### 6-1. 공통 시퀀스

```
[0] 이상 확정 (02 section 5-2)
     ↓
[1] 정지: MRM 등급별 (section 4)          ← 항상 먼저
     ↓
[2] 의존 노드 이상 판정 억제 (section 7)
     ↓
[3] Soft Reset          (분류 A/B 만)
     ↓ 실패 또는 분류 C
[4] Hard Restart + 정보 주입 (section 6-3)
     ↓
[5] 복구 검증 (section 9)
     ↓ 실패 → 재시도 (section 11 한도)
[6] 억제 해제 → 재engage 판정 (section 10)
```

- **[1] 과 [2] 의 순서를 바꾸지 말 것**. 억제를 먼저 걸면 정지 지시가 늦어짐

### 6-2. 노드별 복구

| 노드 | Soft | 정보 주입 | 검증 (section 9) | 특이사항 |
| --- | --- | --- | --- | --- |
| `map_server` | O | 맵 경로 | `/map` 재수신 | 구독자가 latched 를 다시 받음 |
| laser odometry | X | 없음 | 출력 주기 | `ekf` 와 **한 묶음으로 복구**: 따로 살아도 의미 없음 |
| `ekf` | X | 없음 | `odom→base_link` 주기 | 재시작 시 **odom 원점이 바뀔 수 있음** → `map→odom` 저장값 무효화 검토 (section 15) |
| `localization` | 알고리즘별 | `initial_pose_*` + covariance | `tf_settled` + N 초 유지 | section 6-4 |
| `object_detection` | O | 없음 | 발행 주기 | 카메라 재개방 실패가 흔함 → Hard 승격 빠르게 |
| `lane_detection` | O | 없음 | 발행 주기 + confidence | 동일 |
| `global_path_planner` | O | 제어점 파일 | `/path/global` 재수신 | 재발행이 곧 latched 갱신 |
| `local_path_planner` | O | 프로파일 | 발행 주기 | **재시작 전 `global_path_planner` 생존 확인** (section 7-3) |
| `state_machine` | O | **보존 상태 주입** (section 12) | `/state_machine/mission` + `/state_machine/speed_limit` | 주입 실패 시 진행도 소실 |
| `steer_controller` | O | gain set | 발행 주기 + 안전값 | 정지 상태에서만 |
| `speed_controller` | O | 속도 상한 | 발행 주기 + `0` | 정지 상태에서만 |

### 6-3. 정보 주입 · 파라미터로만

```
localization 재시작:
  --ros-args -p initial_pose_x:=...  -p initial_pose_y:=...
             -p initial_pose_yaw:=... -p initial_cov:=...
```

| 규칙 | 이유 |
| --- | --- |
| 토픽(`/initialpose`) 사용 금지 | 구독자 준비 전 발행되면 **유실**. 재시작 직후가 정확히 그 시점 |
| 파라미터로 주입 | `configure` 시점에 확실히 읽힘 |
| covariance 를 `0` 으로 주지 말 것 | 과신하면 필터가 오차에서 빠져나오지 못함 |

### 6-4. `localization` 복구 상세

**저장 대상은 `map→base_link` 가 아니라 `map→odom`**

```
map --[map→odom]--> odom --[odom→base_link]--> base_link
      ↑ localization 발행                ↑ ekf 발행 (별도 프로세스)
        죽으면 소실                        살아남음
```

| 항목 | 내용 |
| --- | --- |
| 저장 대상 | `map→odom` |
| 저장 위치 | **Supervisor 메모리**: 파일 금지 (SD 수명·지연) |
| 저장 주기 | 2 Hz (누적 드리프트 보정값이라 느리게 변함) |
| 저장 항목 | 변환값 + **저장 시각(stamp)** |
| 사용 조건 | `now - stamp < T_stale` (잠정 5 s). 초과 시 `lane_only` 로 전환 (section 3-1) |

**주입값은 저장값이 아니라 합성값**

```
저장:  map→odom  (2 Hz, 느리게 변함)
주입:  map→base_link  =  저장된 map→odom  ∘  현재 odom→base_link
```

- `map→base_link` 를 그대로 저장하면 "죽은 시점 ~ 주입 시점"의 이동량이 통째로 오차
- `ekf` 가 살아 있으므로 `odom→base_link` 가 그 이동을 이미 반영 → **합성하면 정지·주행 여부와 무관하게 정확**
- `state_machine` 이 보관하는 현재 pose (계약 48)는 **로깅·검증용**이며, 주입 원천은 위 합성값
- 이것이 `01` section 9-3 "`localization` + `ekf` 동일 프로세스 금지"의 근거

## 7. 연쇄 오탐 억제 ⚠

### 7-1. 문제

**복구 대상 노드의 출력이 끊기면, 그 출력을 쓰는 노드들이 자동으로 이상 판정됨.**

```
localization 재시작 (수 s)
   → map→odom 끊김
      → local_path_planner 가 TF stale
         → local_path_planner 도 이상 판정
            → local_path_planner 재시작
               → /path/local 끊김
                  → controller 이상 판정 → ...
```

- 억제가 없으면 **하나의 고장이 전 노드 재시작으로 번짐**
- 복구 한도(section 11)를 순식간에 소진해 `TERMINATED` 로 직행

### 7-2. 억제 규칙

| 항목 | 규칙 |
| --- | --- |
| 시점 | 복구 절차 [2] 에서 진입, [6] 에서 해제 |
| 대상 | 복구 대상 노드의 **직접·간접 하위 노드 전체** |
| 억제 범위 | 해당 노드의 **입력 stale 에 기인한 이상 판정만** |
| 억제하지 않는 것 | **프로세스 사망, heartbeat 중단, 자체 진단 `FAULT`**: 이것들은 복구와 무관한 진짜 고장 |
| 최대 억제 시간 | 복구 예산 + 마진 (잠정 15 s). 초과 시 억제 해제하고 전부 재평가 |

- **억제는 "판정을 미루는 것"이지 "무시하는 것"이 아님**. 해제 시점에 전부 다시 평가
- 억제 중에도 차량은 **정지 상태**이므로 안전이 훼손되지 않음
- 주행 중 복구(section 8)에서는 정지 상태가 아니므로 **억제를 쓰지 않음.** 대신 프로파일 전환으로 의존을 끊음

### 7-3. 억제 범위 · 의존 그래프를 두지 않음

**규칙 1개로 끝냄. 노드별 하위 목록을 관리하지 않는다.**

```
억제 진입 ~ 해제 동안:
    복구 대상 노드를 제외한 전 노드의 "입력 stale 기인 이상 판정" 을 보류
```

| 항목 | 규정 |
| --- | --- |
| 억제 대상 | **복구 대상 외 전 노드** (일괄) |
| 억제하지 않는 것 | section 7-2 그대로: 프로세스 사망, heartbeat 중단, 자체 진단 `FAULT` |
| 안전 훼손 여부 | **없음**: 억제 중 차량은 정지 상태 (section 7-2) |

**의존 그래프를 버린 이유**

| 항목 | 판단 |
| --- | --- |
| 정확도 이득 | 정지 상태에서 판정을 미루는 것이므로 **범위를 좁혀서 얻는 안전 이득이 없음** |
| 유지 비용 | 노드 추가·교체(AMCL 전환 등)마다 그래프를 갱신해야 하고, 갱신 누락은 **조용히 연쇄 붕괴로 나타남** |
| 디버깅 | "왜 이 노드가 억제됐나"를 그래프를 짚어가며 추적해야 함. 일괄 억제는 물어볼 필요가 없음 |

- 상한은 그대로 **최대 억제 시간**(잠정 15 s) 하나로 통제. 초과하면 전부 해제하고 재평가

**역방향 제약. 복구 순서**

| 제약 | 이유 |
| --- | --- |
| `local_path_planner` 재시작 전 **`global_path_planner` 생존 확인** | Global Path 는 `transient_local` latched → 발행 노드가 죽어 있으면 **late joiner 가 못 받음** (`02` section 7-2) |
| 둘 다 죽었으면 **`global_path_planner` 먼저** | 순서가 뒤바뀌면 복구 실패 후 한도만 소진 |

## 8. 주행 중 복구 · 정지 원칙의 예외

### 8-1. 성립 조건

`02` section 7-4 의 fallback 이 성립하는 노드에 한해 **정지 없이 재시작**을 허용.

| 조건 | 내용 |
| --- | --- |
| fallback 프로파일 전환 **완료** | 전환 지시 후 `local_path_planner` 가 실제로 반영했음을 확인 |
| 속도 하향 **적용 완료** | `/state_machine/speed_limit` 이 하향값으로 발행되고 있음 |
| 억제 **사용 안 함** | 의존이 이미 끊겨 있으므로 불필요 (section 7-2) |
| 대상 | **`lane_detection`, `global_path_planner`, `map_server` 만** (section 3-1) |

**근거**. "정지 후 복구" 원칙의 이유는 *해당 노드 출력 없이 주행하면 위험하기 때문*임.
fallback 이 성립한다는 것은 그 전제가 성립하지 않는다는 뜻이므로, 정지를 요구하는 것은 일관되지 않음.

**`object_detection` 은 제외**. 초기 검토에서는 포함했으나 `section 3-1` 에서 제외로 확정
- 라바콘 회피가 불가능한 상태로 주행하는 것은 fallback 이 아니라 **무방비 주행**
- 남은 입력으로 "다르게" 주행하는 것과, 필요한 입력 없이 "그냥" 주행하는 것은 다름

### 8-2. `localization` 은 예외의 예외

**`lane_only` 는 복구를 시도하기 전에 들어가는 모드가 아님.**

```
localization 이상 확정
   → `enable` 차단 정지 (FAULT 아님에도 정지)     ← 절대좌표 상실은 즉시 정지
      → Hard Restart + initial_pose 주입
         → 검증
            ├─ 성공 → lane_centering 복귀 → 재engage
            └─ 실패 (한도 소진) → lane_only 전환 → 속도 하향 → 재engage
```

- `lane_only` 는 **완주 시도 모드**이지 정상 주행이 아님 (`02` section 7-4) → 복구 가능성을 먼저 소진
- 정지 상태에서 복구하면 `initial_pose` 주입 정확도가 가장 높음. 움직이면서는 주입 시점 오차가 누적

### 8-3. 절대 허용하지 않는 것

| 대상 | 이유 |
| --- | --- |
| laser odometry, `ekf` | TF 체인의 뿌리. fallback 없음 |
| `local_path_planner` | 재시작 중 경로 공백 → 컨트롤러가 Deadman 으로 정지. 주행 중 의미 없음 |
| `steer_controller` / `speed_controller` | 명령 경로 자체 |
| `state_machine` | 정지 지시 수단을 잃은 채로 재시작 |

## 9. 복구 검증

**재시작 성공 ≠ 복구 완료.** `01` section 5 의 G4 조건을 그대로 쓰되, 안정 유지 시간을 추가.

| 노드 | 검증 조건 | 유지 시간 (잠정) |
| --- | --- | --- |
| `ekf` | `odom→base_link` ≥ 20 Hz | 2 s |
| `localization` | `tf_settled` (+ AMCL 이면 `cov_below`) | **5 s** |
| `lane_detection` | 발행 주기 + confidence ≥ 임계 | 3 s |
| `object_detection` | 발행 주기 + `status = OK` | 2 s |
| `local_path_planner` | 발행 주기 + 경로 유효 | 2 s |
| `state_machine` | `/state_machine/mission` + `/state_machine/speed_limit`, **보존 상태 일치** | 2 s |
| 컨트롤러 | 발행 주기 + 안전값 | 2 s |

- `localization` 이 가장 긺. 잘못 수렴한 pose 로 재출발하면 **경로를 벗어난 채 주행**함
- 검증 실패는 **복구 실패**로 계산 (section 11 한도에 반영)
- 검증 중에는 `/state_machine/enable` 을 발행하지 않음. 검증과 주행 허가를 겹치지 않게

## 10. 재engage

### 10-1. 상황 구분

| 상황 | 처리 |
| --- | --- |
| 출발 전 (`ENGAGED` 미도달) | **신호등 게이트 재평가**: `01` section 4-3 그대로. latch 되지 않았으므로 정상 동작 |
| **주행 중** | **자동 재engage 허용**: 사람이 engage 할 수단이 없음(`run.sh` 단독 실행) |

- 주행 중에는 신호등을 다시 볼 수 없다 → "자동 ENGAGED 금지" 원칙을 적용할 수 없음
- 신호등 latch 는 **복구를 통과해도 유지**된다 (section 12). 복구 후 신호등을 다시 보지 않음

### 10-2. 재engage 조건 (AND)

| 조건 | 값 (잠정) |
| --- | --- |
| 복구 검증 통과 | section 9 |
| 추가 안정 유지 | 2 s (검증 유지 시간과 별도) |
| 억제 해제 후 전 노드 재평가 결과 정상 | - |
| 재engage 횟수 한도 이내 | 3회 |

### 10-3. 재개 속도

| 단계 | 속도 상한 |
| --- | --- |
| 재engage 직후 | **하향값** (fallback 여부와 무관) |
| 정상 유지 T 초 경과 후 | 구간 상한으로 **램프 복귀** |

- 복구 직후는 가장 불확실한 구간. 검증을 통과했다는 것이 완전한 정상을 뜻하지 않음
- T 와 하향값은 section 15

## 11. 한도와 `TERMINATED`

### 11-1. 한도 체계

| 한도 | 값 (잠정) | 초과 시 |
| --- | --- | --- |
| 노드별 Soft Reset | 2회 | **Hard Restart 로 승격** |
| 노드별 Hard Restart | 2회 | **해당 노드 복구 포기** (section 11-2) |
| 백오프 | 1 s → 2 s → 4 s | - |
| 재engage | 3회 | `TERMINATED` |
| 누적 복구 소요 시간 | 60 s | `TERMINATED` |

- 노드별 한도는 **랩 단위로 초기화하지 않음**. 1랩 경기이므로 누적이 곧 전체

### 11-2. 복구 포기 · 노드 단위

section 3-1 의 "복구 불가 판정 시" 열이 곧 이 절의 동작.

| 포기 대상 | 처리 |
| --- | --- |
| `lane_detection` | `global_only` 로 **영구 주행** |
| `localization` | `lane_only` 로 **영구 주행** (도착 판정 없음, 운영자 개입으로 종료) |
| `speed_controller` | `state_machine` 상수 속도 **대행** (section 4-4) |
| `global_path_planner`, `map_server` | 그대로 주행 계속 |
| **그 외 전부** | `TERMINATED` |

- 포기한 노드는 **재시도하지 않음**. 재시도를 계속하면 CPU 를 갉아먹어 살아있는 노드까지 느려짐
- 영구 주행 중에도 **속도 하향은 유지**. 원상 복귀는 복구 성공 시에만

### 11-3. `TERMINATED`

| 항목 | 동작 |
| --- | --- |
| `/state_machine/enable` | **영구 차단** |
| `/state_machine/speed_limit` | `0` |
| 자식 프로세스 | **종료하지 않음**: 상태 보존 |
| Supervisor | **종료하지 않음**: 로그 보존 |
| 로그 | 링버퍼 전체 flush (`02` section 9) |

- `SHUTDOWN`(정상 완주)과 다름. `01` section 11-3
- **실격이 사고보다 낫다.** 불확실한 상태로 주행을 재개하지 않음

## 12. 보존 / 동결 대상

**복구는 Mission 을 리셋하지 않음. 동결했다가 이어받음.**

| 대상 | 처리 | 소실 시 결과 |
| --- | --- | --- |
| 랩 진행도 `s` | **보존** | **도착 판정 불능**: 완주해도 종료 못 함 |
| 신호등 latch (`ENGAGED` 도달 이력) | **보존** | 주행 중 신호등 오검출로 정지 |
| 활성 이벤트 | **보존** | 회피 중이었다면 처음부터 다시 |
| 회피 완료 `index` 집합 | **보존** | 진행도 보조 지표 소실 (종료 조건 아님) |
| 재engage 횟수 | **보존** | 한도 무력화 → crash loop 주행 |
| 현재 프로파일 | **보존** | 복구 직후 잘못된 프로파일로 주행 |
| Behavior 상태 | 리셋 → 기저 기동 | - |

**`state_machine` 재시작 시**

- 위 목록은 **Supervisor 메모리에 상시 미러링**되어야 함. `state_machine` 이 죽으면 그 노드 안의 상태는 사라짐
- 재시작 시 **파라미터로 주입**(section 6-3 규칙과 동일)
- 미러링 주기는 `/state_machine/mission` 발행 주기(20 Hz)에 맞춤
