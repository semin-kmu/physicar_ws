# 07. 인터페이스

`01`~`06`·`09` 에 흩어진 토픽·메시지·서비스·TF 를 **한 곳에 모음.** 이 문서가 인터페이스의 단일 원천이며, 다른 문서의 토픽명은 전부 여기를 참조한다.

**단, 대부분 아직 확정이 아님.** 확정 상태는 section 2-3, 확인 절차는 `08` section 4-0.

> 단위: 길이 **cm** / 각도 **deg** / 속도 **m/s**
> RMW: **`rmw_fastrtps_cpp` 확정.** `rmw_zenoh` **사용 불가** (대회 차량 미설치)

<br>

## 2. 네이밍 규칙

**소유 노드 기준으로 이름공간을 가름.** `kau_state_machine` 패키지가 발행하는 토픽은 전부 `/state_machine/*` 아래에 둠.

| 규칙 | 내용 |
| --- | --- |
| 본 패키지 발행 | **`/state_machine/<항목>`**: 평탄. 중간 계층을 두지 않는다 |
| 타 패키지 발행 | 해당 패키지 규약을 따른다 (`경로_형식.md` section 9.9 등) |
| 형식 | 소문자 `snake_case` |
| 노드 이름공간 | **사용하지 않음**: 노드는 `/system_supervisor`, `/state_machine` 그대로. 토픽 이름만 이름공간을 가진다 |
| 패키지 | `kau_msgs` (소문자, 이미 존재) |

**`/state_machine/*` 로 묶는 이유**

- `ros2 topic list` 에서 **이 패키지가 무엇을 내보내는지 한 줄로 확인**됨. 현장 디버깅의 첫 단계 (`00` 치트시트)
- 발행 주체가 이름에 드러나므로 "누가 이 값을 만들었나"를 묻지 않아도 됨
- 평탄하게 둔 이유: `/state_machine/ctrl/enable` 같은 중간 계층은 경로만 길어지고 구분 이득이 없다 (토픽 7개뿐)

### 2-1. 이름공간 배치

| 이름공간 | 소유 | 항목 |
| --- | --- | --- |
| **`/state_machine/*`** | **본 패키지** | `enable` `speed_limit` `system` `mission` `behavior` `profile` `health` |
| `/path/*` · `/lane/*` · `/viz/*` | `경로_형식.md` section 9.9 **확정본: 변경 금지** | `global` `local` `center` |
| `/perception/*` | `object_detection` | `start_permission` `objects` |
| **루트 평면** | **차량 인터페이스 (대회측 확정)** | `/speed` `/steer`: 우리가 정하지 않는다 |
| `/diag/*` | 전 노드 공유 | `heartbeat` |
| 외부 규약 | 차량·외부 패키지 | `/scan` `/imu` `/map` `/odometry/filtered` `/amcl_pose` |

### 2-2. 이름공간을 붙이지 않는 예외 2건

| 토픽 | 발행 | 이유 |
| --- | --- | --- |
| **`/speed`** · **`/steer`** | `speed_controller` · `steer_controller`<br>(`/speed` 는 대행 시 **`state_machine`**, `03` section 4-4) | **대회측이 정한 차량 인터페이스 토픽.** 우리가 이름을 바꿀 수 없다.<br>대행은 `speed_controller` 가 죽어 `/speed` 가 비었을 때 **같은 이름으로 대신 채우는 것**: 이름을 바꾸면 차량이 받지 못해 대행이 성립하지 않는다 |
| **`/diag/heartbeat`** | 분류 A **7 노드 공유** | 노드별로 쪼개지 않고 **단일 토픽 + `node_id`** 로 구분하는 것이 설계 전제 (`02` section 4-2). 이름공간을 붙이면 노드마다 토픽이 생겨 Supervisor 구독이 1개 → 7개로 늘고, 노드 추가 시 Supervisor 코드를 고쳐야 한다 |

- 즉 **"본 패키지가 소유한 토픽"과 "본 패키지가 발행에 참여하는 토픽"은 다름.** 전자만 `/state_machine/*`

<br>

### 2-3. 이름 확정 상태 ⚠ **대부분 미정**

**타 파트의 토픽명·노드명·패키지명·실행파일명은 아직 확정되지 않았음.** 각 파트 패키지가 완성되면 확인 후 반영.

| 대상 | 상태 | 근거 |
| --- | --- | --- |
| `/state_machine/*` 7개 | **확정** | 본 패키지 소유 |
| 노드 `system_supervisor` · `state_machine` | **확정** | 동일 |
| `/speed` · `/steer` | **토픽명 확정 / 타입 미정** | 대회 차량 인터페이스 (section 5-13) |
| `/perception/start_permission` | **확정** | `object_detection` 파트 회신 |
| `/diag/heartbeat` | **본 패키지가 부과하는 규약** | `02` 계약 19. 각 파트 수용 확인 필요 |
| `/path/global` · `/path/local` · `/lane/center` | **잠정 확정** | `경로_형식.md` section 9.9. 실제 구현과 대조 필요 |
| `/perception/objects` | **미정** | 가정값 |
| 카메라 토픽 | **미정** | 차량 확인 (section 14-2) |
| laser odometry 출력 | **미정** | 노드 자체가 미확정 |
| **전 노드의 노드명·패키지명·실행파일명** | **미정** | `01` section 2-2 는 전부 가정값 |

**이름이 미정이어도 설계는 성립함**

| 장치 | 효과 |
| --- | --- |
| 노드 목록을 `bringup.yaml` 로 관리 (`08` 계약 90) | 이름 확정 시 **YAML 수정만**. Supervisor 코드 불변 |
| 토픽명을 **파라미터 기본값**으로 노출 (계약 79) | 코드 리터럴이 아니므로 교체 비용이 낮음 |
| 시나리오 100 (`ros2 topic list` 대조) | 확정된 이름과 실제 그래프의 불일치를 **기동 전 정적 점검**으로 검출 |

- **이름 불일치는 DDS 가 오류로 알려주지 않음.** 조용히 매칭이 안 되고 stale 로만 나타남 (계약 79)
- `node_id` 는 manifest 이름과 **완전 일치**해야 함 (`02` 계약 20) → 노드명 확정과 heartbeat 감시가 같은 시점에 묶임
- 이름·주기·타입 확인은 **같은 작업**. 절차는 `08` section 4-0

## 3. 토픽 전체 표

> **⚠ 확정된 것은 section 2-3 표에 표시된 것뿐.** 나머지 토픽명·타입·주기는 **가정값**이며,
> 타 파트 패키지 완성 후 `08` section 4-0 절차로 확인해 이 표를 갱신한다.
> 본 문서가 "인터페이스의 단일 원천"이라는 것은 **값이 확정됐다는 뜻이 아니라, 확정되면 여기에 적는다는 뜻**.

### 3-2. 인지

| 토픽 | 타입 | 발행 | 구독 | 주기 | QoS | 근거 |
| --- | --- | --- | --- | --- | --- | --- |

**⚠ `/perception/start_permission` 은 `header` 가 없다**

`std_msgs/Bool` 은 `data` 필드 1개뿐이므로 `header.stamp` 가 존재하지 않음. **`01` 계약 6(전 메시지 `header.stamp` 필수)의 유일한 예외.**

| 항목 | 결과 |
| --- | --- |
| `age` 판정 (`02` section 5-1) | **불가**: stamp 가 없음 |
| `gap` 판정 (수신 중단) | **가능**: 수신 시각은 구독자가 기록 |
| stale 판정 | **`gap` 단독으로 축소** (`04` section 5-2) |
| 놓치는 고장 | `object_detection` 이 **낡은 판정을 계속 재발행**하는 경우. 다만 `true` 는 latch 라 원래 안 바뀌고, `false` 는 안전 방향이므로 **실질 위험 없음** |

- 타입 변경을 요구하지 않음. 이 토픽에 한해 `age` 를 잃는 대가가 **안전 방향**이기 때문
- 나머지 전 토픽은 계약 6 그대로 `header.stamp` 필수

## 4. 가칭 → 정식명 대조표

## 5. 메시지 정의

`kau_msgs/msg/`. **`KauPath.msg` 는 기존 확정본을 그대로 사용하며 본 문서에서 변경하지 않음.**

### 5-1. 공통 규약

| 항목 | 규정 |
| --- | --- |
| `header.stamp` | **전 메시지 필수** = 발행 시각 (`01` 계약 6). stale 판정의 유일한 근거 |
| `header.frame_id` | section 7-3 표의 값 고정 |
| enum | **정수 상수로 명시.** 각 노드가 자체 정의 금지 (계약 88) |
| 기본값 | 0 이 **안전 방향**이 되도록 배치 (`UNKNOWN=0`, `HOLD=0`, `READY=0`) |
| 신뢰도 | `float32`, `0.0 ~ 1.0` |

### 5-2. `Heartbeat` · `02` section 4-1 정식화

```
# 노드 기능 감시. 단일 토픽 /diag/heartbeat 에 전 노드가 발행, node_id 로 구분
# 반드시 노드 자신의 주 tick 안에서 10 Hz 발행 (02 계약 19, 별도 타이머 금지)

std_msgs/Header header              # stamp = 발행 시각

string  node_id                     # bringup manifest 의 노드 이름과 완전 일치 (01 section 2-2, 02 계약 20)

uint8 STATUS_OK       = 0
uint8 STATUS_DEGRADED = 1
uint8 STATUS_FAULT    = 2
uint8   status                      # 노드 자체 진단 결과. 정상 위장 금지 (02 계약 24)

uint32  seq                         # 단조 증가. 재시작 시 0 부터 (02 계약 21)
float32 loop_period_ms              # [ms] 최근 1 s 창의 평균 tick 주기
float32 loop_period_max_ms          # [ms] 최근 1 s 창의 최대 tick 주기 (지터)

InputStatus[] inputs                # 모든 입력 토픽의 상태 (02 계약 22)
string  detail                      # FAULT 사유. 로깅 전용, 판정에 미사용
```

- 상수명에 `STATUS_` 접두사를 붙여 `SystemState.grade` 의 `GRADE_*` 와 구분 (`02` 원문은 `OK`/`DEGRADED`/`FAULT`)
- `inputs` 길이는 노드당 **입력 토픽 수만큼만**. 대역폭 최대 항목이므로 불필요한 항목 금지 (section 9)

### 5-3. `InputStatus` · `02` section 4-1 정식화

```
# 입력 토픽 1개의 관측 상태. 판정하지 않고 사실만 보고 (02 section 2 판정 단일 지점)

string                  name        # 입력 토픽명 (section 3 표의 정식명)
builtin_interfaces/Time last_stamp  # 마지막으로 받은 메시지의 header.stamp
float32                 rate_hz     # [Hz] 최근 1 s 창의 수신 주기
```

- **`stale` 불리언을 두지 않음**. stale 판정은 Supervisor 단독 (`02` section 2, `03` 계약 45)

### 5-4. `SystemState` · `04` section 3-1

```
# System 계층 상태. system_supervisor 가 감시 tick 안에서 20 Hz 발행

uint8 INIT       = 0
uint8 STANDBY    = 1
uint8 ENGAGED    = 2
uint8 DEGRADED   = 3
uint8 STOPPED    = 4                # 정지 + 복구 (구 EMERGENCY + RECOVERY)
uint8 SHUTDOWN   = 5                # speed_limit=0 즉시·정차·종료 (구 COMPLETED 포함)
uint8 TERMINATED = 6
uint8   state

uint8 GRADE_OK       = 0
uint8 GRADE_DEGRADED = 1
uint8 GRADE_FAULT    = 2
uint8   grade                       # 확정된 노드 헬스 등급 (02 section 7-3 max 합성 결과)

- `state_machine` 은 `state` 로 허용 하위 집합을 제한하고(`04` section 3-3), `ENGAGED` 관측으로 자기 latch 를 set (`04` 계약 51)

```

# 컨트롤러 로직은 limit 만 사용. ratio·reason 은 로깅 전용 (01 계약 14)

std_msgs/Header header              # stamp = 발행 시각. stale 판정 250 ms (04 section 6-4)

float32 limit                       # [m/s] 속도 상한. 0 = 정지. 초기값 0 (01 계약 16)

uint8 REASON_STANDBY       = 1      # 출발 게이트 대기 (04 section 5)
uint8 REASON_PROFILE       = 2      # 축소 주행 프로파일 하향 (02 section 7-4)
uint8 REASON_COMFORT_STOP  = 3      # `speed_limit = 0` 정지 감속 (03 section 4-1)
uint8 REASON_STOP_AND_WAIT = 4      # 회피 경로 부재 (06 section 7)

### 5-9. 출발 허가 · **`kau_msgs` 신설 없음**

**`std_msgs/Bool` 표준 타입을 그대로 사용.** `object_detection` 파트 확정 사항이며 본 문서는 인용만 함.

```
# /perception/start_permission  ·  std_msgs/Bool  ·  10 Hz  ·  RELIABLE / KEEP_LAST(1) / VOLATILE

bool data       # false = 출발 금지 / true = 출발 허가
```

| `data` | 의미 (`object_detection` 확정) |
| --- | --- |
| **`false`** | `RED` · `YELLOW` · `UNKNOWN` / 카메라 미수신 · 판별 실패 / `GREEN` 연속 검출이 **5프레임 미만** |
| **`true`** | `GREEN` **5프레임 연속** 검출 → **`object_detection` 내부에서 latch**.<br>카메라 ≈ 15 Hz 기준 약 **0.33 s** 확인.<br>이후 신호등이 사라지거나 `RED`/`YELLOW` 가 되어도 **`false` 로 되돌리지 않음** |

**`kau_msgs` 에 메시지를 만들지 않는 이유**

| 항목 | 판단 |
| --- | --- |
| 정보량 | bool 1개. 커스텀 타입을 만들 근거가 없음 |
| 배포 위험 | `kau_msgs` 는 변경 시 **전 노드 동시 재빌드**가 필요 (section 11-1). 표준 타입은 그 위험이 없음 |
| 대가 | `header` 가 없어 `age` 판정 불가 (section 3-2). 이 토픽에 한해 수용 |

- **색·신뢰도·ROI 를 싣지 않음.** `state_machine` 이 색을 보면 이중 판정이 되어 어긋났을 때 어느 쪽이 맞는지 알 수 없음 (`04` section 5-1)
- 소비 규약은 `04` section 5-2. **`false` · 미수신 을 전부 동일하게 불허**로 처리 (화이트리스트)

### 5-10. `DetectedObject` / `DetectedObjectArray` · `02` 계약 35~38, `05` 계약 63

**크기 표현은 원(반경) 확정.** bbox 를 쓰지 않음.

| 판단 | 근거 |
| --- | --- |
| 원(반경) 채택 | `05` section 6-1 의 경로 간섭 임계가 `라바콘 r + collision_radius + margin` 으로 이미 반경 기반. 라바콘은 축대칭이라 방향 정보가 무의미 |
| bbox 배제 | 회전각 필드가 추가되고, 소비 측이 다시 외접원으로 환산해야 함 |

```

uint32  index                       # 프레임 간 일관 유지. 동일 물체 = 동일 index (02 계약 37)
float32 x                           # [cm] base_link 기준 전방 +
float32 y                           # [cm] base_link 기준 좌측 +
float32 radius                      # [cm] 외접원 반경. 라바콘 7.5

uint8 CLASS_UNKNOWN = 0
uint8 CLASS_CONE    = 1
uint8   obj_class

float32 confidence                  # 0.0 ~ 1.0. 로깅 전용
                                    #   ⚠ 신뢰도 필터링은 object_detection 내부 완결 (02 계약 36)
                                    #      소비 노드가 재판정하지 않는다
```

```
# DetectedObjectArray

std_msgs/Header header              # frame_id: "base_link" 고정
DetectedObject[] objects            # 검출 0개여도 빈 배열로 주기 발행 (01 계약 5)
                                    #   ⚠ "0개" 는 어떤 경우에도 이상 신호가 아니다 (02 section 5-3)
```

- 절대좌표 변환은 **소비 노드가 수행**. `lane_only` 에서 `map` 프레임이 없기 때문 (`02` section 7-4)

### 5-13. `TargetSpeed` / `TargetSteer` · *provisional*

**토픽명은 확정(`/speed`·`/steer`), 메시지 타입은 미확인.** 잠정 정의의 목적은 `header.stamp` 확보 (`02` section 5-3 이 age 100 ms 를 판정한다).

> 차량이 `header` 없는 타입(예: `std_msgs/Float32`)을 요구하면 **age 판정이 불가**해짐.
> 그 경우 stale 판정은 `gap`(수신 중단) 단독으로 축소되며, `02` section 5-1 의 2종 판정 전제가 깨짐. 타입 확인이 필요한 실질 이유

```
# TargetSpeed (provisional)
std_msgs/Header header
float32 speed                       # [m/s] 종방향 목표 속도. 0 = 정지
```

```
# TargetSteer (provisional)
std_msgs/Header header
float32 steer                       # [deg] 목표 조향각. 좌측 +
```

- 차량이 자체 명령 타입(예: `ackermann_msgs/AckermannDriveStamped`)을 요구하면 **그쪽을 따르고 본 정의는 폐기** (section 14)
- `/speed` 는 `03` section 4-4 대행 중에도 **발행자가 정확히 1개**여야 한다 (검증 시나리오 58)

## 7. TF 프레임

### 7-1. 프레임과 발행 주체

| 변환 | 발행 주체 | 주기 | 상실 시 | 근거 |
| --- | --- | --- | --- | --- |
| `map → odom` | `localization` (Cartographer 또는 AMCL) | ≥ 5 Hz | 절대좌표 상실 → 복구 실패 시 `lane_only` | `01` section 5, `03` section 6-4 |
| `odom → base_link` | `ekf` (`robot_localization`) | ≥ 20 Hz | **TF 체인 붕괴 = 전 노드 무효 → `FAULT`** | `01` section 5, `02` section 7-2 |
| `base_link → laser` / `imu` / `camera` | **확정 필요** (차량 제공 static TF 로 추정) | static | 센서 좌표 변환 불가 | section 14 |

- **`map → base_link` 는 아무도 직접 발행하지 않음**. 위 두 변환의 합성. `state_machine` 이 `s` 산출에 사용 (`02` 계약 34)
- 복구 시 저장 대상은 `map → base_link` 가 아니라 **`map → odom`** (`03` section 6-4)
- **동일 프레임 쌍의 발행자가 2개 이상이면 TF 트리가 깨짐**. 검증 시나리오 109

### 7-2. `base_link` 정의

| 항목 | 값 |
| --- | --- |
| 원점 | **후륜축 중심** (`05` section 5-2 의 선분 교차 판정 기준점) |
| 축 | 전방 `+x`, 좌측 `+y`, 상방 `+z` (REP-103) |
| 단위 | **TF 는 ROS 표준 SI(m·rad)**: 팀 단위(cm·deg)와 다름. section 7-4 |

### 7-3. 메시지별 `frame_id`

| 메시지 | `frame_id` | 비고 |
| --- | --- | --- |
| `std_msgs/Bool` (`/perception/start_permission`) | **없음** | `header` 자체가 없음. 계약 6 의 유일한 예외 (section 3-2) |
| `KauPath` (`/path/global`) | `map` | `is_closed = true`, `s_offset = 0` (`05` 계약 59) |
| `KauPath` (`/path/local`) | `map` \| `base_link` | `lane_only` 에서 `base_link` (`09` section 11-1) |
| `KauPath` (`/lane/center`) | `base_link` | 차선은 상대 관측 |
| `DetectedObjectArray` | `base_link` **고정** | `02` 계약 35 |
| `MissionState` | `map` | `last_x`/`last_y` 의 기준 |
| `SystemState` · `BehaviorState` · `SpeedLimit` · `Enable` · `PlannerProfile` · `Heartbeat` · `SupervisorHealth` · `TargetSpeed` · `TargetSteer` | `""` | 프레임 없음. `stamp` 만 사용 |

### 7-4. 단위 경계 ⚠

| 경계 | 규정 |
| --- | --- |
| `kau_msgs` 내부 | **cm / deg / m/s** (팀 통일) |
| TF · `nav_msgs/Odometry` · `sensor_msgs/*` | **m / rad** (ROS 표준) |
| 변환 지점 | **각 노드의 입출력 경계에서 1회.** 내부 연산 중 혼용 금지 |

- 이 경계가 흐려지면 100배 오차가 조용히 통과. `02` section 5-3 의 어떤 임계로도 검출되지 않음
- `04` 계약 57 의 `stopped` 판정(`|v| < 0.05 m/s`)은 `/odometry/filtered` 의 **m/s** 를 그대로 사용

## 8. QoS 결정 근거

### 8-1. 판단 기준

**"유실이 어느 방향으로 작용하는가"** 단 하나로 가름.

| 유실의 방향 | QoS |
| --- | --- |
| 유실 = **안전 방향**(정지에 가까워짐) | **BEST_EFFORT**: 재전송은 지연만 늘림 |
| 유실 = **위험 방향**(직전 값이 유지되어 더 빠르게/더 오래 달림) | **RELIABLE** |
| 유실 = **판정 카운트 왜곡** | RELIABLE + depth 상향 |

### 8-2. 토픽별 근거

| 토픽 | QoS | 근거 |
| --- | --- | --- |
| `/state_machine/enable` | BEST_EFFORT · 1 | **유실이 안전 방향**: 안 오면 Deadman 이 정지시킨다. 최신값만 의미 (`04` section 6-1 확정) |
| `/diag/heartbeat` | BEST_EFFORT · 5 | 누락 1개로 판정하지 않음(연속 3 tick). 재전송은 지연만 늘림 (`02` section 4-2 확정). depth 5 = 10 Hz 발행 × 7 노드 버스트 흡수 |
| `/state_machine/health` | BEST_EFFORT · 1 | GUI 전용 관측. 유실이 주행에 영향 0 (`09` section 2) |
| `/state_machine/speed_limit` | **RELIABLE** · 1 | **유실이 위험 방향**: 낮아진 상한 메시지를 놓치면 컨트롤러가 직전의 **더 높은 상한**을 1 tick 더 유지. `/state_machine/enable` 과 비대칭인 유일한 이유 |
| `/speed` · `/steer` | RELIABLE · 1 | 명령 경로. 유실 = 직전 명령 유지 = 위험 방향. stale 임계도 가장 엄격(100 ms, `02` section 5-3) |
| `/state_machine/system` | RELIABLE · 1 | 전이가 **드문 단발 이벤트**. 1회 유실이 하위 계층 제약을 1 tick 어긋나게 함 |
| `/state_machine/mission` | RELIABLE · 1 | Supervisor 미러링의 유일 원천(`03` 계약 42). 유실 = 복구 주입값 결손 |
| `/state_machine/behavior` | RELIABLE · 1 | gain/weight 전환 지시. 유실 = 전환 누락 |
| `/state_machine/profile` | RELIABLE · 1 | 프로파일 오적용은 경로 기준 자체가 틀어짐 |
| `/perception/start_permission` | RELIABLE · 1 | **`object_detection` 확정 QoS.** 최신 bool 만 의미하고, 프레임 카운트 판정은 그 노드 내부이므로 유실이 카운트를 왜곡하지 않음 |
| `/perception/objects` | RELIABLE · **5** | 동일: `index` 지속성 3 tick 확정(`05` section 6-2). depth 1 은 tick 지터 시 프레임을 삼킨다 |
| `/path/global` | RELIABLE · TRANSIENT_LOCAL · 1 | latched. 재시작 노드가 late joiner 로 수신 (`02` section 7-2·계약 32) |
| `/path/local` · `/lane/center` | RELIABLE · 1 | `경로_형식.md` section 9.9 확정. `/lane/center` 는 `lane_only` 의 유일한 경로 source |
| `/viz/*` | BEST_EFFORT · 1 | RViz 전용. 유실이 주행에 영향 0 |

### 8-3. 내구성 · 이력

| 항목 | 규정 |
| --- | --- |
| TRANSIENT_LOCAL | **`/path/global` · `/map` 2개뿐.** 그 외 전부 VOLATILE |
| History | 전 토픽 `KEEP_LAST` |
| depth 기본 | **1**: 최신값만 의미. 예외는 `/diag/heartbeat`(5), `/perception/*`(5) |
| Deadline / Lifespan / Liveliness | **사용하지 않음**: 판정은 Supervisor 단일 지점(`02` section 2). DDS 에 판정을 위임하면 판정 주체가 둘이 된다 |

### 8-4. GUI 구독

| 항목 | 규정 |
| --- | --- |
| reader QoS | 가능한 한 **BEST_EFFORT 요청** (RELIABLE writer 와 호환) + depth 1~2 (`09` section 9) |
| 금지 | GUI 구독을 이유로 **차량 측 writer QoS 를 바꾸지 않는다** (`09` 계약 103) |
| 대용량 토픽 | 카메라 원본·`/scan` 은 기본 미구독, 명시적 토글 (`09` section 10-2) |
