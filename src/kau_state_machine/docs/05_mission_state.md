# 05. Mission State

`state_machine` 노드가 소유하는 **미션 진행 상태**의 정의와 판정.
System 상태 전이는 `04`, Behavior 상태는 `06`.

<br>

## 1. 범위

| 포함 | 미포함 |
| --- | --- |
| `READY → DRIVING → FINISHED` 전이 · guard · entry/exit | System 상태 전이, 신호등 판정 → `04` |
| 구간(Section) + 이벤트(Event) 구성 | Behavior 상태 (`HOLD`/`LANE_KEEPING`/`AVOID_OBSTACLE`/`STOP_AND_WAIT`) → `06` |
| 랩 진행도 `s` 산출 (`state_machine` 직접) | 토픽·메시지 필드 정의 → `07` |
| **도착 판정** (순회 트랙) | mission profile **YAML 스키마** → `08` |
| `OBSTACLE` 이벤트 진입·해제 | 회피 경로 생성 → `local_path_planner` |
| `/state_machine/speed_limit` 산출·전파 | 이상 검출 → `02`, 복구 절차 → `03` |
| 정지거리 예산 | |

- **단위: 길이 cm / 각도 deg / 속도 m/s**
- 경로는 quintic Bezier 제어점(`kau_msgs/KauPath`). **샘플링하지 않음** (`docs/경로_형식.md` 대전제)
- **모든 수치는 잠정**. 근거를 함께 적었으며 확정 작업은 section 13

## 2. 상태

### 2-1. 전이도

```
READY ──(System ENGAGED)──→ DRIVING ──(도착 판정, section 5)──→ FINISHED
                               ↑                            │
                               └── 복구 중에도 유지 (동결)   └── 최종 상태 (latch)
```

| 항목 | 규정 |
| --- | --- |
| 역전이 | **없음.** `DRIVING → READY`, `FINISHED → DRIVING` 모두 금지 |
| 복구 중 | Mission 은 **`DRIVING` 유지**. 복구는 Mission 을 리셋하지 않음 (`03` section 12) |
| System 과의 관계 | Mission `FINISHED` 도달이 System `SHUTDOWN` 전이를 **유발** (`04` T8). 이름 중복 금지 |
| 평가 | **20 Hz 단일 tick.** 발행도 같은 tick 안에서 (`01` 계약 18) |

### 2-2. guard · entry · exit

| 상태 | entry action | exit action | 다음 전이 guard |
| --- | --- | --- | --- |
| `READY` | `/state_machine/speed_limit = 0` 발행 시작<br>`s` 전역 탐색 1회로 초기화 (section 4-3)<br>회피 완료 집합 비움, 활성 이벤트 0 | 없음 | System == `ENGAGED` |
| `DRIVING` | `t0 = now`<br>`s_mono ← s`, `lap = 0`<br>구간 index 0 (`LANE_SECTION`) 진입<br>`/state_machine/speed_limit` = 구간 상한 × 프로파일 비율 | 활성 이벤트 **강제 해제** | section 5 도착 판정 (AND 조건) **OR** section 5-4 2차 조건 |
| `FINISHED` | `/state_machine/speed_limit = 0` **즉시** (`03` section 4-1)<br>Behavior 기저 `HOLD` (`06`) | - | 없음 (최종) |

- `READY` entry 는 `01` section 5 의 G4 판정 조건(`mission_state == READY` AND `speed_limit == 0`)과 동일 상태
- `FINISHED` 도 **`0` 즉시**. 도착선 통과 후이므로 기록에 영향이 없고, 부드럽게 설 이유도 없다 (`03` section 4-1)

### 2-3. DRIVING tick 순서

```
20 Hz tick:
  1. TF map→base_link 수신 확인          (없으면 s 갱신 skip, section 4-4)
  2. s 갱신: window 추적 → s_mono 누적   (section 4)
  3. 도착 판정                            (section 5)
  4. 이벤트 판정: 진입 / 해제            (section 6)
  5. 속도 상한 산출                       (section 7)
  6. /state_machine/speed_limit + /state_machine/mission 발행   ← tick 끝
```

- **6번이 tick 끝에 있는 것이 핵심**. 1~5 중 어디서든 멈추면 발행이 끊겨 컨트롤러가 stale 로 정지 (`01` section 14-1 대응 A, `02` section 8-1 과 동일 구조)

## 3. 구성 = 구간 + 이벤트

### 3-1. 확정 구성

| 요소 | 확정 | 개수 |
| --- | --- | --- |
| 구간 | `LANE_SECTION` **단독** | 항상 1 |
| 이벤트 | `OBSTACLE` **단독** | 0 또는 1 |

- 삭제 확정: `CONE_SECTION` / `free_space` / `TRAFFIC_LIGHT`(→ `04` 출발 게이트) / `MARKER` / `SIGN` / `INTERSECTION` / `PARKING`
- 이벤트가 1종이므로 **우선순위·선점·스택 로직 불필요.** 복귀 주소는 항상 `LANE_SECTION`

### 3-2. 구간이 1개여도 시퀀스는 데이터로 유지

| 항목 | 규정 |
| --- | --- |
| 구간 시퀀스 | **배열**로 보관. 길이 1도 배열 |
| 현재 구간 | 배열 index. `LANE_SECTION` 을 코드 상수로 두지 않음 |
| 종료 조건 | 구간마다 데이터로 지정. 길이 1 + 폐곡선 → 종료 조건 = **도착 판정** |
| 근거 | 코드 상수화하면 규정 변경 시 `state_machine` 수정 필요. 설정 교체로 끝나야 함 |

### 3-3. 구간별 설정값 (의미만, 스키마는 `08`)

| 항목 | 의미 | 소비 지점 |
| --- | --- | --- |
| 속도 상한 | 구간의 **절대 상한 [m/s]**. 프로파일 비율의 기준 | section 7 |
| Planner 프로파일 | 기본 프로파일 (평시 `lane_centering`) | `local_path_planner` |
| 허용 이벤트 | 이 구간에서 평가할 이벤트 목록 | section 6 |
| 종료 조건 | 다음 구간 전환 또는 `FINISHED` 판정 기준 | section 5 |

## 4. 랩 진행도 `s`

### 4-1. 최근접점은 각 노드가 따로 구한다 · 공유하지 않음

**같은 "최근접점"이라도 대상 곡선·주기·용도가 전부 다름.** 그래서 아무도 남에게 발행하지 않고 각자 필요한 만큼 구함 (`02` 계약 33).

| 노드 | 대상 곡선 | 주기 | 용도 | 정밀도 요구 |
| --- | --- | --- | --- | --- |
| `steer_controller` | **Local Path** | **100 Hz** | 조향 오차 | 최고: 제어 루프 |
| `local_path_planner` | **Global Path** | 미정 | reference 구성 | 중 |
| `lane_detection` · `object_detection` | 각자 필요 시 | 자체 주기 | 자체 판정 | 자체 결정 |
| **`state_machine`** | **Global Path** | **20 Hz** | **랩 진행도 `s` · 도착 판정** | 낮음: 종료 트리거 |

- `state_machine` 이 100 Hz 로 돌 수 없으므로 **컨트롤러에 최근접점을 공급할 수 없음.** 반대로 컨트롤러의 100 Hz 결과는 Local Path 위 값이라 **전역 진행도와 무관**하다
- 중복 계산처럼 보이나 **곡선이 다르므로 중복이 아님.** 공유하면 주기 불일치가 판정 지연으로 전이되고, 공급 노드 재시작마다 진행도가 흔들림

**`state_machine` 의 `s` 산출**

| 항목 | 내용 |
| --- | --- |
| 입력 | TF `map→base_link` + **latched Global Path** (`KauPath`, `is_closed = true`, `s_offset = 0`) |
| 주기 | **20 Hz** (평가 tick 과 동일): 낮추지 않는 근거는 아래 |
| 알고리즘 | 호길이 **window 추적** (`경로_형식.md` section 8.4). 전역 탐색이 아님 |
| 금지 | `global_path_planner` / `local_path_planner` 로부터 **받아쓰지 않는다** |

**5 Hz 로 낮추는 안. 검토 후 기각**

진행도 판정은 정밀도 요구가 낮으므로 주기를 낮출 여지가 있어 보이나, **window 반경이 주기에 반비례해 커짐.**

| 주기 | 1 step 이동 | FWD 반경 | 자기근접 185.5 cm 대비 |
| --- | --- | --- | --- |
| **20 Hz (채택)** | 10 cm | **120 cm** | 여유 66 cm ✓ |
| 10 Hz | 20 cm | 200 cm | **초과** ✗ |
| 5 Hz | 40 cm | 360 cm | **초과** ✗ |

| 항목 | 판단 |
| --- | --- |
| 잃는 것 | window 반경이 자기근접 거리를 넘으면 **반대편 분기가 window 에 진입** → `s` 도약 (section 8.4: 횡오차 155 cm 에서 971 cm 도약 실측) |
| 얻는 것 | CPU **0.26 % → 0.065 %**, 절감폭 **0.19 %p** |
| 결론 | **얻는 것이 없다.** 0.2 %p 를 아끼려고 진행도 도약 위험을 사는 교환 |

- 자기근접 185.5 cm 는 **시뮬 트랙 기준**(예시값, section 13). 실트랙이 더 좁으면 20 Hz 에서도 재검토 필요
- 도착 판정 해상도도 10 cm → 40 cm 로 나빠짐
- **주기를 낮춰야 할 실제 이유가 생기면** window 중심을 이동거리로 예측 전진시켜 반경을 줄이는 방법이 있으나, 지금은 도입할 이유가 없음

### 4-2. 단조 증가 `s_mono`

```
delta_s = ((s_k − s_{k−1}) mod L + L/2) mod L − L/2      ← 최소표현 (section 8.4)
s_mono += delta_s
lap     = floor(s_mono / L)
진행도   = s_mono / L                                     ( = (lap·L + s) / L )
```

| 항목 | 값 | 근거 |
| --- | --- | --- |
| `L` | `KauPath.total_length` (시뮬 참값 2722.5 cm) | 실트랙 미확정 (section 13) |
| 1 tick 이동 | **10 cm** | 2.0 m/s ÷ 20 Hz |
| `delta_s` 상한 | ≪ `L/2` | 10 cm vs 1361 cm: wrap 오판이 구조적으로 불가능 |
| 후퇴 감시 | `delta_s < −20 cm` 이 연속 3 tick | 차량은 후진하지 않음 → window 추적 이상 의심 → 전역 탐색 1회 |

- **wrap 값 `s` 를 그대로 진행도로 쓰면 출발선 부근에서 판정이 무너짐**. `s_mono` 가 유일한 진행도 원천
- `delta_s` 를 최소표현으로 산출하지 않으면 wrap 시점에 후퇴로 오판 (section 8.4, 1.5바퀴 실측 오판 0회)

### 4-3. window 파라미터 · 20 Hz 용으로 재산출

`경로_형식.md` section 8.4 의 값은 **100 Hz 제어기 기준**이므로 그대로 쓸 수 없음.

| parameter | section 8.4 (100 Hz) | `state_machine` (20 Hz) | 근거 |
| --- | --- | --- | --- |
| 1 step 이동 | 2 cm | **10 cm** | 2.0 m/s ÷ 20 Hz |
| drop-out 허용 | 10 step (20 cm) | **3 tick (30 cm)** | 3 tick 초과 결손은 `02` section 5-2 의 stale 판정 대상: window 로 흡수할 문제가 아님 |
| 코너 컷 여유 | 20 cm | 20 cm | 동일 |
| 안전율 | 2배 | 2배 | 동일 |
| **FWD** | 100 cm | **120 cm** | (10 + 30 + 20) × 2 |
| **BACK** | 50 cm | **60 cm** | FWD 의 1/2 |
| **GATE** | 250 cm | 250 cm | 경로 이탈 판정 거리 |
| 실패 판정 | 연속 3회 | 연속 3회 | 동일 |

- **상한 검증**: window 반경 120 cm < 경로 최소 자기근접 거리 **185.5 cm** (section 8.4) → 반대편 분기가 window 에 진입 불가
- window 상실(GATE 초과 연속 3회, `state_machine` 재시작) 시 **전역 탐색 1회**(convex hull 하한 B&B, section 8.3) 후 추적 재개. **매 tick 전역 탐색 금지**

### 4-4. 연산 비용

| 연산 | 실측 근거 | 20 Hz 부하 |
| --- | --- | --- |
| 최근접점 (window + AABB) | **129 µs** (section 8.8, Python) | 2.58 ms/s ≈ **0.26 % CPU** |
| 전역 탐색 1회 | **0.40 ms** (section 8.3, 70 segment 기준) | tick 예산 50 ms 의 **0.8 %**: 1 tick 안에서 완결 |

- `02` section 7-2 의 "0.2 ms × 20 Hz ≈ 0.4 %" 는 보수 가정. 실측 근거로 대체해도 결론 동일. **무시 가능**
- Global Path 는 30 m / 약 30 segment (`경로_형식.md` section 9.10) → 70 segment 기준값보다 유리
- `cum_s` · `hull` 은 **수신 시 1회 산출**해 보관 (section 9.4). 매 tick 재계산 금지

### 4-5. TF 결손 · `lane_only`

| 상황 | 처리 |
| --- | --- |
| `map→base_link` 1~2 tick 결손 | `s_mono` 유지, 갱신 skip. 도착 판정도 skip |
| 3 tick 이상 결손 | `02` section 5-3 stale 판정으로 승계: Mission 은 별도 판단하지 않음 (`03` 계약 45) |
| **`lane_only` 프로파일** | **`s_mono` 동결.** 추정 진행도를 만들지 않음 (`02` section 7-4 확정) |
| `lane_only` → 복구 | 전역 탐색 1회로 `s` 재획득, `s_mono` 를 절대 기준으로 복귀 → 도착 판정 재가동 |

## 5. 도착 판정 ⚠

**도착선 = 출발선.** 출발 직후 도착 판정이 성립해 버리는 것이 순회 트랙 최대 함정.

### 5-1. AND 조건 (1차)

> ⚠ 표시 항목은 **시뮬 예시값에서 유도**된 것. 실측 전에는 도착 판정 자체를 신뢰할 수 없다 (section 13)

| # | 조건 | 값 (잠정) | 근거 |
| --- | --- | --- | --- |
| A | **랩 진행도 가드** | `s_mono / L ≥ 0.90` | 주 조건. 코너 컷·오차로 0.95 를 못 채우는 경우 대비해 0.90 |
| B | **출발선 근방 진입** | 선분 교차 판정에 흡수 (section 5-2) | `s` 단독 근방 판정은 wrap 부근에서 애매 |
| C | **진행 방향 통과** | 1 tick 변위 · 출발선 법선 > 0 | 역방향·정지 중 진동 배제 |
| D | **최소 경과 시간** | `now − t0 ≥ 12 s` ⚠ | 이론 최소 랩타임 = 전장 ÷ 구간 상한, 그 0.9배.<br>**전장 2722.5 cm 는 예시값**(section 13) → 실측 트랙 전장으로 재산출 필수 |

### 5-2. 출발선 통과 = 선분 교차 판정

**`s` 만으로 판정하지 않음**. wrap 근처에서 `s ≈ 0` 과 `s ≈ L` 이 인접해 근방 판정이 애매해짐.

```
출발선  = map 프레임 유향 선분 (P_a → P_b),  법선 n = 진행 방향 +
차량 변위 = ( x[k−1] → x[k] )                x = base_link 원점 (후륜축)

통과 = seg_intersect( x[k−1], x[k], P_a, P_b )  AND  ( (x[k] − x[k−1]) · n > 0 )
```

| 항목 | 값 (잠정) | 근거 |
| --- | --- | --- |
| 차량 변위 세그먼트 길이 | 10 cm | 2.0 m/s ÷ 20 Hz. 선분 폭 안에서 반드시 1회 교차 |
| 출발선 폭 `W` | **140 cm** ⚠ | 차선폭 × 2: 회피로 차선을 벗어나도 놓치지 않기 위함.<br>**차선폭 70 cm 는 예시값**(section 13) → 실측값 × 2 로 재산출. 이탈 허용이 반대 차선까지 열렸으므로(`06` section 6-2) **주행가능 폭 전체를 덮을 것** |
| 법선 `n` | Global Path `s = 0` 지점의 접선 | 접선은 제어점에서 해석적으로 산출 (section 9.7) |
| 출발선 좌표 | **설정값** (mission profile, `08`) | 경로에서 유추하지 않음: 폭·방향이 결정되지 않음 |

- 연산은 2D 선분 교차 1회. **비용 무시 가능**
- `x[k−1]` 이 없으면(재시작 직후 첫 tick) 그 tick 은 교차 판정을 **skip** → 계약 68

### 5-3. `lane_only` 에서는 도착 판정을 하지 않는다 · 확정

| 항목 | 확정 (`02` section 7-4) |
| --- | --- |
| 문제 | `map→base_link` 부재 → `s` 산출 불가 |
| 결정 | 도착 판정 **미수행**. 추정 진행도도 만들지 않음 |
| 동작 | `s_mono` 동결, **지속 주행**. 자동 정지·자동 종료 **없음** |
| 종료 | **운영자 개입** (차량 들어올림 / 프로세스 종료) |
| 근거 | 드리프트가 있는 추정 진행도로 종료를 판정하면 **트랙 한복판 오종료** |

### 5-4. 2차 조건 · 교차 판정 유실 대비

```
진행도 ≥ 1.02   →   선분 교차 없이도 FINISHED
```

| 항목 | 내용 |
| --- | --- |
| 목적 | `state_machine` 재시작·TF 결손이 통과 순간과 겹쳐 **교차 이벤트를 놓치는** 경우 |
| 놓쳤을 때의 대안 | 다음 랩까지 27 m 를 더 주행: 훨씬 나쁨 |
| 안전성 | `1.02` 는 출발선을 **54 cm 지난 지점**. 기록 계측은 이미 종료된 상태 |
| 종속 | 진행도 ≥ 1.02 는 A(≥0.90)·D(12 s)를 자동 포함, 단조 `s_mono` 가 C(방향)를 함의 → **가드가 약해지지 않음** |
| 로깅 | 2차 조건으로 종료한 경우 **반드시 경고 기록**: 1차 판정 실패의 유일한 단서 |

## 6. `OBSTACLE` 이벤트

### 6-1. 진입 조건 = 검출 **AND** 경로 간섭

**검출만으로 진입하면 도로 옆 정적 물체에 계속 반응.**

| 조건 | 판정 | 값 |
| --- | --- | --- |
| 검출 | `/perception/objects` 에 존재 | `object_detection` 이 신뢰도 필터링을 **내부 완결** → 재판정 없음 (`02` 계약 36) |
| 경로 간섭 (횡) | 장애물 중심의 경로 최근접 횡거리 `\|e\|` | `< lateral_threshold` (아래 식) |
| 경로 간섭 (종) | 전방 호길이 | `0 ~ (L_plan + preview)` |

```
lateral_threshold = r_cone + collision_radius 11.04 + margin 10
종 범위 상한      = L_plan + preview
```

| 기호 | 값 | 상태 |
| --- | --- | --- |
| `collision_radius` | 11.04 cm | **확정**: 차량 제원 |
| `margin` | 10 cm | 잠정 정책값 |
| `r_cone` | ? | **미확정**: 시뮬의 7.5 cm 는 **예시값** |
| `L_plan` + `preview` | ? | **미확정**: `L_plan` 1.5~5 m 검토 중. 시뮬 통일값 150 + 150 = 300 cm 를 **계산 예시로만** 사용 |

- **임계가 차선 안팎을 실제로 가르는지는 차선 반폭 실측 후에만 판단.** 시뮬 값으로 "전부 포착된다"고 결론짓지 않음 (section 13)
- 판정 대상 곡선: `lane_centering` / `global_only` → **Global Path**, `lane_only` → **Lane Path**
  - `object_detection` 이 `base_link` 상대좌표로 발행하므로(`02` 계약 35) `map` 없이도 성립

### 6-2. 확정 · 해제

**⚠ 단위는 tick 이 아니라 `/perception/objects` 프레임**. 입력 10 Hz, 평가 tick 20 Hz 로 주기가 다름

| 항목 | 값 (잠정) | 근거 |
| --- | --- | --- |
| 확정 | **연속 3 프레임** 동일 `index` (절대시간은 검출 주기에 종속) | 아래 |
| 판정 축 | **`index` 지속성** (신뢰도 아님) | 신뢰도는 `object_detection` 내부 완결 (계약 36). `index` 는 프레임 간 일관 (계약 37) |
| 해제 | 미검출 **10 프레임 (1.0 s)** | `02` 의 "복귀 10 tick" 히스테리시스와 동일 패턴 |
| min dwell | **1.0 s** | 진입 직후 복귀 방지 |
| min gap | **0.5 s** | 해제 직후 재진입 진동 차단 |

**tick 이 아니라 프레임으로 세는 이유**

| 방식 | 10 Hz 입력 · 20 Hz tick 에서의 실제 의미 |
| --- | --- |
| "연속 3 tick" (구 정의) | 150 ms 창에 **검출 프레임이 1~2개**뿐 → 사실상 **1프레임 확정**. debounce 가 이름만 존재 |
| **"연속 3 프레임" (채택)** | 실제로 서로 다른 3개 관측을 요구. **검출 주기와 무관하게 의미가 보존됨** |

- `02` section 5-2 의 "3 tick" 과 **같은 상수를 쓰되 단위가 다름.** 입력 주기가 다르면 같은 숫자가 같은 의미가 아니므로 단위를 명시
- **위험 방향으로 빠르게(3 프레임), 안전 방향으로 느리게(10 프레임)**. `02` section 5-2 와 같은 패턴
- 확정 지연이 150 ms → **300 ms 로 늘어남** → section 8-1 정지거리 예산에 반영

### 6-3. 재진입 방지 · 처리 완료 기록

| 항목 | 규정 |
| --- | --- |
| 재진입 방지 주체 | **경로 간섭 조건**이 담당: 회피하면 경로에서 벗어나 **자연 해제**됨 |
| 처리 완료 기록 | **불필요**: 완료 목록으로 재진입을 막는 구조를 만들지 않음 |
| 별도 쿨다운 | min gap 0.5 s 만. 그 이상은 두지 않음 |
| 근거 | 완료 목록으로 막으면 **동일 라바콘을 다시 만나야 하는 상황에서 회피 불능** |

### 6-4. 회피 완료 `index` 집합 · 진행도 보조 지표 전용

| 항목 | 규정 |
| --- | --- |
| 용도 | **로깅 · 진행도 보조 지표만** |
| **종료 조건 사용** | **절대 금지**: 오검출/누락 1회로 미션 종료 불능 |
| 기대 개수 | 라바콘 **6개 확정** (`Notes/State_Machine_확정.md`) |
| 6 초과 | 오검출 의심 → **경고 로깅만.** 판정에 사용하지 않음 |
| 6 미만으로 완주 | 정상 종료: 도착 판정은 `s_mono` 와 선분 교차만 본다 |

### 6-5. Behavior 로의 전달

- 활성 이벤트(`OBSTACLE` / 없음)와 `index` 를 **Behavior 계층에 전달만** 함
- `AVOID_OBSTACLE` / `STOP_AND_WAIT` 전환 규칙·차선 이탈 허용은 **`06` 소관**. 여기서 서술하지 않음

## 7. 속도 상한 전파

### 7-1. 발행 규약

| 항목 | 값 |
| --- | --- |
| 토픽 | `/state_machine/speed_limit` (`01` section 4-3 의 정지 2계층 중 하나) |
| 주기 | **20 Hz**: 평가 tick **안에서** 발행. 별도 타이머 금지 (`01` 계약 18) |
| 초기값 | **`0`**, `ACTIVE` 직후부터 발행 (`01` 계약 16) |
| 수신측 | `speed_controller`: stale timeout 250 ms 초과 시 `limit = 0` (`01` 계약 17) |
| 사유 enum | 동반 발행하되 **로깅 전용.** 컨트롤러 로직은 값만 사용 |

### 7-2. 값 = 구간 상한 × 비율

**절대값은 구간 상한 하나만 둠.** 나머지는 전부 비율로 유도. 상한이 바뀌어도 문서·설정 수정 불필요.

| 상황 | 비율 | 절대값 (상한 **2.0 m/s 가정**) | 출처 |
| --- | --- | --- | --- |
| `lane_centering` (평시) | **100 %** | 2.00 | `02` section 7-4 |
| `global_only` | **60 %** | 1.20 | `02` section 7-4 |
| `lane_only` | **40 %** | 0.80 | `02` section 7-4 |
| `speed_controller` 대행 | **25 %** | 0.50 | `03` section 4-4: `/speed` 직접 발행 |
| `READY` / 출발 게이트 대기 | 0 % | 0.00 | `01` section 4-3 |
| `speed_limit = 0` 정지 / `STOP_AND_WAIT` / `FINISHED` | 0 % | 0.00 | `03` section 4-1 |
| 재engage 직후 | 하향값 (`03` section 10-3) | 미정 | `03` section 15 |

- **2.0 m/s 는 규정 미확인 가정값**. 시뮬 속도 제어 상한(`src/README.md`)과 동일하게 잡은 것
- 대행(25 %)은 `/state_machine/speed_limit` 이 아니라 `/speed` 채널이지만 **같은 비율 체계**를 쓴다

### 7-3. 복수 사유 합성 = 최솟값

```
speed_limit = min( 구간 상한 × 프로파일 비율,
                   정지 지시 출력,
                   재engage 하향값,
                   이벤트 지시값 )
```

- **안전 방향으로만 합성.** `02` section 7-3 의 등급 `max` 합성과 같은 원리 (속도는 부호가 반대)
- 사유 enum 은 **최솟값을 만든 항목**을 기록

### 7-4. `OBSTACLE` 활성 중 추가 감속을 두지 않는다 · 결정

| 항목 | 내용 |
| --- | --- |
| 결정 | 이벤트 진입만으로 속도를 낮추지 않음 |
| 근거 1 | 감속 시작이 **이벤트 확정 지연만큼 늦어** 정지거리 단축 효과가 작다 (section 8) |
| 근거 2 | 회피 곡률 증가는 `speed_controller` 의 **곡률 기반 감속**이 이미 반영 (`src/README.md` 속도 제어) |
| 대안 | 예산은 `L_plan + preview` 로 확보 (section 8). 300 cm 는 **시뮬 잠정값**: `L_plan` 확정 시 재계산 |
| 재검토 조건 | section 8 예산이 실측에서 성립하지 않으면 도입 (section 13) |

## 8. 정지거리 예산

**진입 지연이 곧 충돌 여유** (`02` section 5-3). `LANE_SECTION` 기저 기동에는 회피가 없으므로 이벤트 진입 실패·지연이 그대로 충돌이 됨.

### 8-1. 반응 지연 (2.0 m/s = 200 cm/s)

| 단계 | 지연 (잠정) | 이동거리 | 근거 |
| --- | --- | --- | --- |
| **검출 ~ 이벤트 확정 (연속 3 프레임)** | **TBD** (10 Hz 면 300 ms) | **TBD** (60 cm) | section 6-2. 첫 프레임 취득 포함. **검출 주기 미정** |
| 평가 tick 1회 + 발행 | 50 ms | 10 cm | 20 Hz |
| `local_path_planner` 재계획 | **TBD** | **TBD** | 주기 미정 (`08` section 4-0). 계약 64 는 **상시 고정**만 확정 |
| 컨트롤러 반영 + 조향 응답 τ | 110 ms | 22 cm | 100 Hz + τ 0.1 s (`src/README.md`, 잠정) |
| **소계** | **460 ms + 재계획 주기** | **92 cm + α** | |

- **검출과 확정을 합쳐서 셈**. 첫 검출 프레임이 확정 3프레임의 1번째이므로 따로 더하면 이중 계상
- 확정 단위를 tick → 프레임으로 바꾸면서 이 항목이 **150 ms → 300 ms 로 증가** (section 6-2)
- **재계획 주기가 이 예산의 유일한 미지수.** 10 Hz 면 560 ms / 112 cm, 5 Hz 면 660 ms / 132 cm, 2 Hz 면 960 ms / 192 cm

### 8-2. 필요 검출거리

```
필요 = 반응 이동거리 + 회피/정지 소요 + 충돌 여유
충돌 여유 = r_cone + collision_radius 11.04        (r_cone 미확정)
```

| 소요 | 값 (잠정) | 산출 |
| --- | --- | --- |
| 회피 기동 종거리 | **약 95 cm** | 횡 30 cm 이동, quintic `κ_max ≈ 5.77 d / L²` ≤ `κ_max` 0.020221 /cm |
| 정지 소요 (`STOP_AND_WAIT`) | **100 cm** | `v²/2a`, `a = 2.0 m/s²` **가정**: 실측 미확보 |
| 충돌 여유 | **≈ 20 cm** (계산 예시) | `r_cone` 을 시뮬 예시값 7.5 로 두었을 때. **실측 후 재대입** |

→ 정지가 회피보다 길다. **정지를 예산 기준으로 잡음.**

| 재계획 주기 | 필요 검출거리 | 가용 예고 300 cm 대비 |
| --- | --- | --- |
| 10 Hz | 112 + 100 + 20 = 232 cm | 여유 68 cm |
| 5 Hz | 132 + 100 + 20 = 252 cm | 여유 48 cm |
| 2 Hz | 192 + 100 + 20 = 312 cm | 여유 −12 cm: **불성립** |

> **`local_path_planner` 재계획 주기가 확정되어야 이 표에서 한 줄을 고를 수 있다** (`08` section 4-0).
> 2 Hz 는 이미 불성립이므로, 실측이 그 근처로 나오면 **구간 상한을 낮추는 것 외에 수단이 없음** (section 8-3)

- **Local Path 길이는 1.5~5 m 검토 중**. 예고거리가 늘면 여유도 비례해 늘어남
- 실제 상한은 **`object_detection` 의 라바콘 검출거리**이며 미확인 (section 13)
- `충돌 여유 20 cm` 는 **예시값 기반**(`r_cone` 7.5 미확정). 판정식만 유효, 실측 후 대입 (section 13)

- 가용 예고거리 = `L_plan` + `preview`. **`L_plan` 미확정**이라 시뮬 잠정값 150 + 150 = 300 cm 사용 (section 13)
- 결론: **재계획 주기 상시 고정이 계약 사항** → 계약 64. 이벤트 중 상향은 두지 않음. 조건부 주기는 검증 대상만 2배로 늘림. **값은 `08` section 4-0 실측 대기**
- **미지수가 2개: 감속도 `a` 와 재계획 주기.** `a` 가 절반이면 정지거리 200 cm 로 **어떤 재계획 주기에서도 예산 초과**. 감속도 실측 전에는 이 예산을 근거로 속도 상한을 올리지 말 것 (section 13)

### 8-3. 감시로는 해소되지 않는 위험

- 검출 성능 저하는 Supervisor 가 관측할 수 없다 (`02` section 5-3 구조적 한계)
- 대응은 감시가 아니라 **이 절의 예산**. 예산이 안 맞으면 **구간 상한을 낮추는 것**이 유일한 수단
